Nova Widget Embed Test v28.0

This page demonstrates the Nova Website Widget SDK embedded as a third-party script. The widget loads in a Shadow DOM (isolated from this page's styles), persists session in localStorage, and respects per-tenant config.

Test mode: This page is served from the Nova origin itself (same-origin). To verify cross-origin CORS, host this HTML on a different domain or open it via file://.

1. Try the widget

Click the chat bubble in the bottom-right corner to start. Switch tenants and the widget will reload with the new tenant's branding, welcome message, and suggestions.

2. Embed code

Copy this snippet onto any HTML page. Replace your-nova.com with your Nova server URL and cleaning-demo with your tenant ID.

<script
  src="https://your-nova.com/widget.js"
  data-tenant="cleaning-demo"
  data-position="bottom-right"
  data-color="#10b981"
  async>
</script>

3. Optional data attributes

The widget reads these attributes from the script tag (all optional, override tenant config):

  • data-tenant — required, your tenant ID
  • data-position — bottom-right (default) or bottom-left
  • data-color — hex color for the bubble + header (e.g. #10b981)
  • data-language — auto (default), english, or roman_urdu
  • data-welcome — override the welcome message

4. Security features

  • Shadow DOM isolation — host page CSS cannot leak in, widget CSS cannot leak out
  • XSS-safe rendering — all user/assistant text rendered via textContent, never innerHTML
  • Tenant-scoped sessions — localStorage keys are nova-widget:<tenantId>, no cross-tenant data leakage
  • CORS preflight — server handles OPTIONS for cross-origin embeds
  • Rate limiting — 30 messages per minute per IP+tenant, returns 429 with Retry-After
  • Tenant verification — server rejects requests for unknown tenant IDs with HTTP 404
  • Customer ID validation — server enforces ^[a-zA-Z0-9_-]+$, max 128 chars
  • Message length cap — 4,000 chars per message (server-enforced)
  • No PII collected — customer ID is a random UUID, no name/email/phone stored client-side
  • CSP headers — default-src 'none'; script-src 'self' on /widget.js

5. Availability features

  • Retry with backoff — 3 retries on network failure (1s, 2s, 4s delays)
  • 15s request timeout — prevents hung requests
  • Graceful degradation — if config endpoint is unreachable, widget uses defaults and shows an error bubble
  • Session persistence — conversation survives page refresh, expires after 7 days
  • State recovery — if server restarts (memory mode), widget generates new customerId and resumes cleanly
  • Message queue — rapid-fire messages are queued and sent sequentially
  • Async load — never blocks page render
